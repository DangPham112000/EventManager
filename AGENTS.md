# Event Manager - Project Requirements and Planning (PRP)

This file (`AGENTS.md`) serves as the primary context and planning document for AI agents and developers working on the Event Manager project.

## 1. Project Overview
An Event Manager application where users can create, manage, and participate in events. A key feature is the integration with Google Calendar to synchronize events seamlessly.

## 2. Core Features & Requirements
*   **Authentication:**
    *   Login and Registration exclusively using Google Authentication.
*   **Event Management:**
    *   Users can create new events (Title, Description, Start Time, End Time, Location).
    *   Users can update or delete their own events.
*   **Participation:**
    *   Users can browse available events.
    *   Users can join/participate in events created by others.
*   **Google Calendar Sync:**
    *   Events created or joined in the application should automatically sync with the user's Google Calendar.

## 3. Tech Stack Requirements
*   **Frontend:** React 19, Vite, TypeScript, TailwindCSS, shadcn ui, React Router DOM, Apollo Client (for GraphQL), Redux Toolkit (state management), lodash.
*   **Backend:** Node.js, Express, Apollo Server (GraphQL), TypeScript.
*   **Database:** MongoDB (via Mongoose).
*   **Deployment:** Docker, Docker Compose, Nginx, GitHub Actions.

## 4. API Specifications (GraphQL)

### Entities

**User**
*   `id`: ID!
*   `email`: String!
*   `name`: String!
*   `avatar`: String
*   `googleId`: String!

**Event**
*   `id`: ID!
*   `title`: String!
*   `description`: String
*   `startTime`: String! (ISO Date)
*   `endTime`: String! (ISO Date)
*   `location`: String
*   `creator`: User!
*   `attendees`: [User!]!
*   `googleEventId`: String (For Google Calendar sync reference)

### Queries
*   `me: User` - Get current logged-in user profile.
*   `getEvents: [Event!]!` - Get a list of events.
*   `getEvent(id: ID!): Event` - Get details of a specific event.

### Mutations
*   `loginWithGoogle(token: String!): AuthPayload` - Handle Google login/registration.
*   `createEvent(input: CreateEventInput!): Event!`
*   `updateEvent(id: ID!, input: UpdateEventInput!): Event!`
*   `deleteEvent(id: ID!): Boolean!`
*   `joinEvent(eventId: ID!): Event!`
*   `leaveEvent(eventId: ID!): Event!`

## 5. Deployment Strategy
*   **Containerization:** Both Frontend and Backend will be dockerized.
*   **Frontend Serving:** Nginx will be used to serve the static files generated by Vite.
*   **Orchestration:** `docker-compose.yml` will manage the Frontend, Backend, Nginx, and MongoDB (if not using Atlas) services.
*   **CI/CD Pipeline (GitHub Actions):**
    1.  Trigger on push to the `main` branch.
    2.  Build Docker images for Frontend and Backend.
    3.  Push images to a Docker registry (e.g., Docker Hub or GitHub Container Registry).
    4.  SSH into the target VPS.
    5.  Pull the latest Docker images.
    6.  Run `docker compose up -d` to restart services with the new images.
    7.  Execute `docker image prune -a -f` to clean up old images and free up space on the VPS.
